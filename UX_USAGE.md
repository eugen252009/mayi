# UI candidate usage

`mayi-approve status` is a compact observation, not an authorization or process inventory. `--details` exposes all old counters; `--json` is unchanged. `--watch` uses ANSI only on a recognized TTY. `--watch --plain` explicitly chooses append-only human snapshots without ANSI, including redirected/dumb terminals. Use `--watch --json` for NDJSON. A detailed ANSI canvas that cannot fit is rejected with a plain-mode/resize suggestion rather than drawing invisible data. `status --preflight` codes/semantics are unchanged.

Approval screens support the measured 30x8 minimum through lossless data pagination and short chrome; every page retains executor identity, page/details hints and decision controls. Space toggles details, [/] page, a approves pending requests in the current set, d asks for denial selection, q quits. Expanded controls expose follow-up, skip and numeric subsets. Pending rows are presented before dependency context, but ORIGINAL displayed index numbers are retained and broker ordering, decisions, exact digests/argv and human/PAM requirements are unchanged. Queue-update notices are reserved in the same bounded canvas and do not replace the current request set. Queue context labelled RUNNING is shown as dispatched/start-unconfirmed in this view, not inferred as actual child start. Small screens may show only part of a command on a page; inspect every relevant argument/path across pages before deciding. Nothing infers command effects.

Requester animation is bounded to its actual stderr terminal width; no animation on unsupported or redirected stderr. History human rq_v2 labels use `rq:<nonce-prefix>`, not the shared epoch prefix. These are abbreviations, NEVER lookup identifiers. Full IDs remain in JSON and request detail. UNKNOWN is an unconfirmed historical outcome, not live pending work; MAYI/EXIT separates broker result and child exit status. Epoch separators remain virtual. Human watch errors leave the alternate screen before being printed, so fallback advice remains visible. Unsized PTYs use an explicit positive80x24 fallback even on Python3.9. No JSON/schema or privileged-interface changes.

Below 30x8, a complete human review cannot be promised; use a larger terminal. Plain/no-ANSI output and deliberate technical detail dumps may require scrollback. Error guidance never recommends automatic replay of uncertain work. No lifetime, identity, capability, broker-restart or execution semantics changed.
