# Mayi security boundary — exact-command MVP

## Active boundary

- Python is an unprivileged proposal client. `mayi <command> [args...]` preserves the synchronous path; `--queue` sends the same one exact executable/argv operation asynchronously. Python policy and request digests grant no authority; the broker creates queue IDs.
- Rust owns immutable request, challenge, approval view, expiry, status, and one-shot consume state. It obtains PID/UID/GID from `SO_PEERCRED` and resolves the authenticated UID through NSS for `mayi-requester` or `mayi-approver` group membership on every connection, including primary and supplementary groups. Lookup is uncached; NSS failure is internal error and an unknown/nonmember UID is denied.
- Before any broker socket connection or request display, `mayi-approve` requires stdin/stdout TTYs and a controlling terminal, checks that the actual calling UID belongs to the NSS-backed approver group, and authenticates that same UID's NSS username through the dedicated PAM service `mayi-approve`. PAM conversations read password responses directly from `/dev/tty` with echo disabled; echo-on, unsupported prompts, terminal errors, account denial, or PAM errors fail closed. No password is taken from argv, environment, or piped stdin. Successful authentication is held only in the console process; exit/restart requires fresh authentication. This establishes a local authenticated-console gate, not a persistent session/token or a change to the broker protocol.
- After that gate, the console connects to the broker, obtains fresh broker-rendered views, verifies broker/request/view correlations, and presents queue DAGs topologically with exact executable/argv, requester UID, dependencies, and privileged executor identity UID 0 / primary GID 23012. `a/s/d/f`, aliases `y/n/e`, numeric selections, and `q` control it; skip is navigation only. Denial/follow-up produce no executor request. Actual requester and approving UIDs remain bound to request/view state; group membership grants a role but does not replace identity. Broker peer-UID, approver-group, and one-shot view checks remain independently enforced.
- The synchronous broker consume path and asynchronous dependency scheduler forward only the immutable stored `exec` operation to a separate root executor. Queue execution starts once only after approval and all dependencies succeed; terminal unsuccessful parents block descendants. The executor checks `SO_PEERCRED` for broker UID 23002, repeats strict schema/path/argv checks, persists a replay claim before spawn, clears the environment, and executes directly without shell interpretation. Requester/approver accounts cannot access the executor socket directory; peer UID validation remains authoritative if a process with directory group access tries to connect.
- The package enables only the closed `exec` request schema. Service/package action strings, arbitrary command strings, requester-controlled privileged environment, and caller-supplied consume argv are not accepted. This is nevertheless a broad human-gated policy: a human may approve any trusted root-owned executable and its exact argv, including an explicitly requested shell executable.
- Executor output is capped at 64 KiB per stream. The broker waits up to 300 seconds, but the child has no runtime deadline and the executor handles requests serially; a longer-running child can leave the requester with an unknown result and block later requests until it exits. The journal claims IDs before spawn and suppresses duplicate IDs across restarts. Mayi does not retry ambiguous execution; a child is not transactional and receives no rollback guarantee.
- Queued jobs/results are in-memory broker state, not a durable queue. Broker restart invalidates queued approvals and status history, and no job is replayed. `--wait` is observation-only; its failure budget counts terminal non-success states, and `--fail-instant` does not cancel other jobs.

## Trust limitations and deployment

`SO_PEERCRED` authenticates an OS UID, not a process binary, nor protection from compromise of that UID. PAM authentication protects entry to the installed human approval console but cannot distinguish processes sharing an authenticated account, and it does not replace broker peer credentials or group authorization. The broker UID, root executor, executable trust directories, PAM stack, and root-controlled NSS role-group configuration are in the trusted computing base. Root-owned tools can have surprising behavior; the display is not a semantic policy engine. The package keeps broker UID/GID 23002/23012 and executor UID 0 fixed; requester and approver groups are GIDs 23011 and 23013. A user may belong to both role groups. Inspect group-ID collisions and provision the intended human memberships before deployment. Mayi 0.4.0 requires glibc >=2.28, Python >=3.7, and `libpam0g` >=1.1.8 and `libpam-runtime`; its native executables retain the Debian 10 GLIBC_2.28 build floor. PAM account policy must be available through `/etc/pam.d/mayi-approve`; missing or rejecting policy fails closed. See [DEBIAN_COMPATIBILITY.md](DEBIAN_COMPATIBILITY.md) for tested releases and OS lifecycle caveats.

The exact 0.4.0 artifact (`d0a28d1e0e46837f395bc687b93f76742a91056a33358a5201b5a6ca28946f86`) passed disposable Debian 10–13 systemd qualification, including fresh install and 0.3.2 upgrade, PAM authentication, same/separate approver accounts, TTY/credential-channel failures, conffile lifecycle, runtime/queue regressions, and systemd/socket lifecycle. Trixie additionally passed upgrades from 0.2.0 through 0.3.1. Containers used systemd as PID 1, private cgroups, no host mounts, and no runtime network. No publication or deployment occurred, and the real host was not accessed or modified for this milestone.

## Filesystem executor gate

The filesystem executor remains disconnected and independently **INCOMPLETE**. Its documented syscall-failure and cleanup-outcome gaps are still open. No real-root filesystem executor handoff is enabled. Do not describe the filesystem executor as qualified or connect it as a consequence of this command MVP.
