# History design

`mayi history` is a Python-standard-library read-only projection of the existing native journal. It never connects to either broker socket, authenticates an approver, executes a request, restores a capability or reads the executor claim ledger.

Options: default latest 20 identities; --limit 1..1000; --all up to 2000 identities in the bounded window; --request full rq_ ID (all matching boot/instance namespaces); --since journalctl timestamp; --status case-insensitive state; --json schema v1. --all and --limit conflict. The reserved word history can still be executed as an executable with `mayi -- history ...`.

Reader invokes fixed /usr/bin/journalctl with an argument vector, --no-pager, JSON, --reverse, --lines=20000, --all and early native schema/transport/unit/UID matches. It deliberately does not use --system/--user: system-service records can be stored in UID-split journals (broker UID 23002). Kernel unit/UID filtering, not file partition, establishes scope. This does not grant access to files the caller cannot already read. User timestamps are one bounded --since=value argument, never shell input. Environment contains only fixed C locale/color settings. stdout and stderr are incrementally drained with selectors; per-line bound 64 KiB, total 16 MiB, deadline 20 seconds. At most 20,000 projected events and 2,000 identities; scan and identity omission counts are exposed. No persistent cache/database. Default limit bounds presentation, not scanning; this preserves older lifecycle context within the window. --all does not promise unlimited retention access.

All journal data is untrusted. Only typed allowlisted native fields are retained; MESSAGE, command line, reasons, environment and process output are never projected. Trusted unit and emitting UID are checked, as are boot/instance/identifier shapes and numbers. Malformed rows increment ignored_records. Controls/non-ASCII are escaped in human output; JSON uses ASCII escapes. Tables use terminal width (80 when redirected), no ANSI/color/spinner, with safe wrapping and explicit ellipses. Full IDs are in --request/JSON.

Observed nonterminal states are displayed PENDING?/APPROVED?/RUNNING? with status UNKNOWN in JSON. They never assert present broker state. Terminal success requires an authoritative execution-finished event with matching successful state and normal child exit 0 (broker also Mayi result 0). View approval alone is not execution. VIEW_EXPIRED is not request EXPIRED. Denial/expiry/blocked/follow-up use their actual broker events. Contradictory terminal facts become UNKNOWN. No CANCELED state is invented because the protocol has no such transition.

Statuses: SUCCEEDED, FAILED, DENIED, EXPIRED, BLOCKED, EXPLAIN_REQUESTED, UNKNOWN. Observed states also PENDING, APPROVED, RUNNING. --status pending/approved/running filters that observation, not live state. Aliases: success, failure, pending_approval, proposed, ready, waiting_dependency, execution_unknown, explained.

Journal rotation, volatile storage, rate limits, process death, boot boundaries and bounded scans can remove events. Output always warns that history is incomplete and not live; there is no state recovery or replay. Correlation is explicitly scoped (HISTORY_CORRELATION.md). Root/compromised service can forge application assertions; trusted metadata is attribution, not cryptographic audit proof.
