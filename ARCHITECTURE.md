# Mayi architecture — Protocol 5 exact-command approval MVP

1. The `mayi` Python CLI resolves a command using a fixed trusted path, canonicalizes it, preserves exact structured argv, and proposes one `exec` operation. Ordinary `mayi <command> [args...]` remains synchronous; `mayi --queue` submits it asynchronously and returns a broker-generated opaque request ID. Neither path interprets shell syntax, forwards requester environment/cwd, or decides approval.
2. The Rust broker obtains peer PID/UID/GID from `SO_PEERCRED`, authorizes requester role through NSS-backed `mayi-requester` membership, validates strict schemas/path/argv bounds, and stores immutable operation data bound to the actual requester UID. Queue dependency IDs must belong to that same UID; cycles and invalid dependencies are rejected.
3. The persistent approver console's peer UID is authorized through NSS-backed `mayi-approver` membership. It displays exact executable/argv, requester UID, IDs, and connected dependency sets in topological order. `a/s/d/f`, aliases `y/n/e`, numeric selections, and `q` control the console; skip affects only local navigation. Every decision uses a fresh one-shot view bound to the actual approving UID. `SO_PEERCRED` authenticates an OS UID, not a process or human.
4. Synchronous requester polls its own state; its approval permits one `APPROVED → CONSUMED` transition and consume of the exact stored request. For a queue, broker-owned scheduler state starts an approved command only when all dependencies succeeded. Non-success terminal dependencies block descendants. `--wait` and `--status` are requester-bound observers; `--fail-instant` does not cancel jobs.
5. For the stored `exec` operation only, the broker connects to a separate privileged executor. The executor checks broker UID 23002 with `SO_PEERCRED`, validates the closed request schema and executable again, durably claims the one-shot request ID, clears the environment, and launches directly with `execve` semantics. The process runs as UID 0 / primary GID 23012; stdin is `/dev/null`, cwd is `/`, and output is bounded. Ambiguous handoffs are never retried.
6. Queue state/results reside in broker memory; broker restart invalidates them and they are not replayed. Existing structured filesystem operations remain disconnected and return `EXECUTION_DISABLED`; the filesystem core's independent qualification remains **INCOMPLETE**.

## Trust and operation limits

This is a broad human-gated MVP, not a semantic command allowlist. Any approved root-owned executable in the configured trusted directories can run. The approver must inspect the displayed argv; explicitly requesting a shell binary can run a shell, although Mayi never interprets a command string itself. A command may partially affect system state before failure or a lost response. `SO_PEERCRED` cannot distinguish processes sharing a UID or establish human identity. A compromised broker UID or privileged executor is inside the trusted computing base.

Package identities keep broker UID/GID 23002/23012 and executor UID 0 fixed; requester and approver groups use GIDs 23011 and 23013. Inspect for collisions and add only intended human users to role groups; the package does not assign membership automatically. Package 0.3.1 requires libc >=2.28 and Python >=3.7; both native executables require at most GLIBC_2.28. The identical package artifact passed disposable systemd qualification on Debian 10 through 13. Debian 10 is technically compatible but EOL; current OS security support is a separate policy, detailed in [DEBIAN_COMPATIBILITY.md](DEBIAN_COMPATIBILITY.md). The administrator subsequently reported deployment and a queue/approval/privileged-execution smoke test on the real Debian 12.15 host; this source consolidation did not access or modify it.

The earlier targeted review of the authorization plane applies to that historical base revision, not an independent review of this new privileged command path. The later operator-reported host smoke test included privileged command execution; no live filesystem mutation was reported.
